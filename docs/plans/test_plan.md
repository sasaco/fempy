# テスト拡充計画

更新日: 2026-09-10

この文書は、現行テストで未検証または一部検証となっている範囲を拡充するための方針を示す。
現在の保証範囲は[テスト項目表](test_items.md)、実際の配置と収集数は
[現行テスト台帳](test_inventory.md)、実行方法は[tests/README](../../tests/README.md)を正本とする。
整理前の計画は[履歴資料](archive/test_plan-original.md)に保存している。

## 優先順位

1. 公開APIが誤結果を成功として返す経路を、独立解を持つ最小再現から修正する。
2. 要素と解析種別の未対応組合せを、計算開始前に要素ID付きで拒否する。
3. VTKのセル型、節点・要素対応、変位・反力・応力・断面力配列を独立に検証する（PQ-06完了）。
4. 結果へ単位系、解析条件、収束状態、警告を追跡できるメタデータを加える（PQ-08完了）。
5. メッシュ収束は独立参照解で計測済み（PQ-09）。次に単位換算（PQ-10）と性能（PQ-12）を、
   正しさの検証と分けて計測する。
6. 外部実験資料を得た後に材料非線形の較正を行う。

具体的な実施順序と完了条件は[プロダクト品質ロードマップ](product-quality-roadmap.md)の
PQ-06〜12に従う。GF-01〜05で解消済みの一般FEM不具合は再開せず、外部較正GF-06だけを
PQ-11から参照する。

## テストの構成

| 層 | 目的 | 期待値 |
|---|---|---|
| unit | 要素行列、材料則、ソルバー分岐、入出力の局所契約 | 手計算、解析式、不変量 |
| integration | 公開モデルの組立、境界、解析、後処理 | 製品コードに依存しない参照 |
| regression | 保存入力と履歴の意図しない変化を検出 | 出典・hash付きの承認済み参照 |
| oracle | 独立実装と原資料そのものを検証 | 高精度計算、原演算子、外部資料 |
| harness | 収集、比較、manifest、CI判定の失敗検出 | 意図的に壊した入力と終了コード |

製品ソルバーの現在値から期待値を再生成しない。重根の固有モードは部分空間で比較し、
メッシュや単位の検証は変位だけでなく反力・内力・応力も確認する。skip、比較項目削除、
許容誤差の緩和で完了扱いにしない。

## 変更ごとのゲート

- 局所変更は所有するunitと関連integrationを実行する。
- 数値共通処理、参照値、manifest、配布候補の変更後は全件pytestを実行する。
- README／Wikiのコード変更後は`tools.validation.check_wiki`と隔離wheel例を確認する。
- 参照更新では入力同一性、出典、更新前後hash、理由を記録する。
- JUnit、終了コード、環境、実行時間を検証報告へ残す。
- 現在の件数は実行結果と台帳から取得し、過去の固定件数を成功根拠にしない。

## 標準コマンド

```powershell
uv sync --locked --extra dev
uv run --locked --extra dev pytest tests
uv run --locked --extra dev python -m tools.validation.check_wiki
uv run --locked --extra dev python -m tools.validation.check_test_results
```

必須依存がないために自動skipする構成にはしない。Node.jsを用いる原JavaScript比較などを
除外する場合は、部分実行であることをコマンドと報告の両方に明記する。

## 完了記録

各項目の完了時に、対象コミット、環境、参照モデル、期待値の独立性、コマンド、成功・失敗・
skip数、終了コード、残る制約を`docs/report/`へ記録する。同時にロードマップ、項目表、台帳、
ユーザー向け保証範囲を更新する。過去の報告は当時の証拠として書き換えない。
