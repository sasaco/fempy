# 設計実務での利用手順

[Wikiホーム](index.md) · [要素と解析の選び方](elements.md) · [モデルの入力](data-structures.md) · [結果の読み方](results.md)

このページは、FEMPythonの解析結果を設計検討へ使うときに、入力から照査記録まで何を確認するかをまとめたものです。
計算が正常終了しても、モデル化、荷重条件、評価方法が設計目的に合っているとは限りません。
解析担当者と照査担当者が、同じ入力と判断根拠を再現できる状態を完了条件にします。

## 適用範囲を最初に決める

最初に、解析で求める量とFEMPythonの対応範囲を照合します。

| 設計上の目的 | 主な解析 | 確認する結果 |
|---|---|---|
| 梁・柱の変位、反力、断面力 | 線形静解析、梁要素 | 節点変位、支点反力、梁端力 |
| 床版・壁の変位、応力、断面合力 | 線形静解析、T3/Q4シェル | 節点変位、上下表面応力、断面合力、辺の合力 |
| 立体部材の応力 | 線形静解析、対応するソリッド | 節点変位、積分点応力・ひずみ |
| RC梁の剛性低下と履歴 | 材料非線形解析、非線形梁 | 段階変位、反力、端力、中央断面曲率、収束履歴 |
| 固有周期とモード形 | 固有値解析 | 固有値、振動数、周期、モード形、固有対残差 |

要素と解析の組合せは[機能対応表](elements.md)を正本とします。「実装済み（個別検証未完了）」の組合せを
設計値へ使う場合は、対象モデルに即した独立比較を追加してください。

FEMPythonは、設計基準に基づく荷重生成、荷重組合せ、最不利包絡、断面照査、許容値判定を自動では行いません。
これらは採用する基準、照査方法、組合せ係数を別に管理し、解析結果との対応を記録します。

## 推奨する作業順序

| 段階 | 作業 | 残す記録 |
|---:|---|---|
| 1 | 設計条件と評価量を決める | 構造系、解析種別、荷重ケース、採用基準、評価位置 |
| 2 | 単位、座標、要素、支持を定義する | 単位表、軸図、要素・材料・支持一覧 |
| 3 | 小さな確認モデルを解く | 手計算または独立解との比較 |
| 4 | 本モデルをケースごとに解析する | 入力JSON、結果JSON、ログ、結果メタデータ |
| 5 | 釣合い、変形、断面力・応力を照査する | 照査表、異常値の説明、対象外結果の明記 |
| 6 | メッシュ・モデル化の感度を確認する | 粗・標準・細モデルの比較 |
| 7 | 入力、結果、判断を固定する | 使用版、hash、最終入力、結果、照査記録 |

## 1. 計算条件を固定する

解析前に、少なくとも次を一枚の計算条件表へ記録します。

- 解析の目的、対象部位、評価する限界状態
- `static`、`material_nonlinear`、`modal`の別
- 長さ、力、時間、質量、応力の一貫単位系
- 全体XYZ軸、梁のi端・j端、シェル・ソリッドの節点順序
- 材料値、断面値、板厚、密度の出典
- 支持、ばね、材端解放、強制変位の根拠
- 荷重ケース名、荷重方向、組合せ係数、同時載荷の範囲
- 評価する節点、部材、断面、シェル面、積分点

`model.model_metadata["units"]`には、実際に採用した単位名を記録できます。[結果メタデータ](results.md)へ
その宣言が引き継がれます。自動換算は行われないため、宣言と数値の整合は解析者が確認します。

## 2. 入力モデルを確認する

大規模モデルへ進む前に、同じ要素、単位、支持、荷重方向を使った小さなモデルを解きます。
片持ち梁、単純支持梁、一様ひずみ、一定応力など、独立解を得られる問題を選びます。

本モデルでは次を確認します。

- 節点の重複、要素の退化、極端な長短辺、シェル法線、ソリッド節点順序
- 梁局所軸と`Iy`・`Iz`、部材荷重の局所／全体方向
- 拘束不足による剛体運動と、過剰拘束による意図しない反力
- 支持ばね、強制変位、材端解放が対象自由度へ設定されていること
- 梁断面積・断面二次モーメント、シェル板厚、材料定数、密度の単位
- 着目点や荷重位置による部材分割後も、評価位置を追跡できること

モデル規模、要素数、自由度数は`model.get_model_info()`で確認します。入力ファイルの行数や結果辞書の長さを
モデル規模の代わりに使わないでください。

## 3. 荷重ケースを分ける

一回の解析は一つの荷重条件です。編集用JSONの`load`に複数ケースがあっても先頭だけを選ぶため、
設計上の各ケースを一つずつ取り出して解析します。ケースごとの結果から組合せ・包絡を作る処理は、
採用した基準と係数を明示した別の計算として管理します。

荷重ごとに、合力、作用位置、全体原点回りモーメント、正負の向きを先に手計算します。
節点荷重、部材荷重、シェル面圧、線荷重・面荷重を同じケースへ入れる場合は、各荷重の内訳と総和を残します。

### 線荷重・面荷重

設計実務での主な確認点は次のとおりです。

- 空間荷重は`static`だけに使用する。`material_nonlinear`と`modal`へは適用しない。
- 傾斜面では`plane`を明示し、全ての構造節点、載荷節点、経路点が同一平面上にあることを確認する。
- `direction: normal`では節点順序から法線が決まる。代表セルの法線を数値または図で確認する。
- 非凸外周、穴、独立載荷メッシュを使う場合は、載荷領域を図示して面積を別計算する。
- 独立載荷メッシュは載荷領域だけを定め、剛性や自由度を増やさないことをモデル説明に記す。
- 梁またはT3/Q4シェルへの配分を設計利用の標準とし、他要素への配分は個別検証を追加する。

結果の`spatial_load_contribution`で、荷重別の載荷長さ・載荷面積、`resultant`、`moment`、
節点側の合力・モーメント、保存誤差を確認します。他の荷重を併用した反力との比較では、
空間荷重だけの確認ケースも作り、空間荷重の合力と支持反力を分離して照合します。
入力方法と監査項目の詳細は[線荷重・面荷重](spatial-loads.md)を参照してください。

## 4. 解析結果の成立を確認する

成功結果では、最初に次を確認します。

1. `metadata.analysis.type`が意図した解析種別である。
2. `metadata.solver.converged`が`true`で、警告と相対残差を確認した。
3. `metadata.input_sha256`を入力・結果の管理表へ記録した。
4. 変位の方向と変形形が、荷重・支持条件から予想した形になっている。
5. 支点反力の合力・モーメントが外力と釣り合う。
6. 梁端力、シェル断面合力、ソリッド応力の評価位置と座標系を確認した。

ゼロに近い値、反力の符号、梁端力のi端・j端、シェルの局所座標、ソリッドの積分点を区別します。
最大値だけを抜き出す前に、[結果の読み方](results.md)で出力位置と成分順序を確認してください。

HTTP 200や`converged: true`は、設計条件との一致や工学的妥当性を保証しません。未知キーが入力経路によって
無視される場合もあるため、正規化保存したモデルを再読込し、要素数、支持、荷重、結果が一致することを確認します。

## 5. メッシュとモデル化の感度を確認する

変位、反力、代表断面力・応力について、少なくとも粗・標準・細の三段階を比較します。
要素寸法を変えるときは、支持、荷重の合力・作用位置、評価位置を変えません。

- 全体変位と反力は、モデル全体の挙動を確認する指標にする。
- 梁の着目断面は同じ実座標で比較する。
- シェル・ソリッド応力は、支持点、集中荷重点、角部などの特異点から離れた位置も比較する。
- ピーク応力が細分化のたびに増える場合は、一点値を設計値として収束したと判断しない。
- 線荷重・面荷重では、構造メッシュと載荷メッシュを別々に変え、荷重配分と構造応答の影響を分ける。

採用する収束許容値は、設計目的、評価量、規準、モデル化誤差に応じて計算書で定めます。
FEMPythonが一律の合否値を設定するものではありません。

## 6. 独立計算と照合する

少なくとも一つ、FEMPythonと同じ実装に依存しない比較を用意します。

- 梁の変位・反力・断面力を閉形式解または骨組計算で比較する。
- シェル・ソリッドの一定応力状態、対称性、合力を確認する。
- 固有値を単自由度近似、理論解、または別ソルバーと比較する。
- 材料非線形では骨格曲線、載荷順序、残留変形、エネルギー、収束段階を比較する。
- 重要なモデルは、別の担当者が入力条件と主要結果を再計算する。

差が出た場合は、単位、支持、局所軸、荷重方向、評価位置、要素定式化、メッシュの順に切り分けます。
単に許容差を緩めて一致としないでください。

## 7. 保存する成果物

設計計算の再現に必要な最小セットを保存します。

| 成果物 | 内容 |
|---|---|
| 計算条件表 | 目的、適用基準、単位、座標、材料・断面、支持、荷重ケース、評価位置 |
| 元入力 | 受領または作成した編集用JSONと、その版・作成元 |
| 解析入力 | ケースごとに固定した入力JSON、またはモデル生成スクリプト |
| 正規化モデル | `model.save_model()`で保存した再読込可能なJSON |
| 解析結果 | `model.save_results()`のJSONと必要な図表 |
| 実行環境 | `metadata.product.version`、Python版、使用wheelまたはGitコミット、依存環境 |
| 同一性 | `metadata.input_sha256`と、配布する入力・結果ファイルのhash |
| 照査記録 | 釣合い、独立解、メッシュ感度、異常値、採否判断、担当者・照査者 |

エラーや警告が出た試行を削除せず、最終採用結果と区別して残します。入力・結果の保存方法は
[ファイル入出力・VTK](file-formats.md)、原因の調べ方は[エラーと対処](error-handling.md)を参照してください。

- [ ] 解析目的、採用基準、評価量を明記した。
- [ ] 使用する要素と解析の組合せが対応表で検証済みである。
- [ ] 単位系、全体軸、局所軸、節点順序を確認した。
- [ ] 材料、断面、板厚、密度、支持条件の出典を残した。
- [ ] 荷重ケースを一件ずつ固定し、合力・作用位置・モーメントを別計算した。
- [ ] 小さな確認モデルが独立解と一致した。
- [ ] 変形形、反力、端力・応力の符号と評価位置を確認した。
- [ ] 外力と支点反力の合力・モーメントが釣り合った。
- [ ] 粗・標準・細モデルで主要結果の感度を確認した。
- [ ] 特異点のピーク値を無条件に設計値へ採用していない。
- [ ] 入力、結果、メタデータ、使用版、hash、照査記録を保存した。

## 使用を止めて見直す条件

次の場合は結果を採用せず、モデルまたは解析方法を見直します。

- 対応表で未対応の要素・解析組合せが必要である。
- 機構、数値悪条件、未収束を示す例外や警告を解消できない。
- 外力と反力が釣り合わない、または保存誤差を説明できない。
- メッシュを細かくしても主要結果が安定しない。
- 独立計算との差を、単位・座標・モデル化・評価位置から説明できない。
- 大変形、座屈、時刻歴、曲面上の空間荷重、移動荷重包絡など、現行機能の外側が支配する。
- 設計基準が求める非線形性、組合せ、照査式を別途扱えない。

この場合は[エラーと対処](error-handling.md)で診断情報を整理し、問題を保った小さな再現モデルを作ります。
